# L2 串行重构审计（2026-09-22）

历史记录：下文描述 2026-09-22 的 admission 实测协议，现已由
`serial-batch-card-review-v3` 替代。当前流程见 ARCHITECTURE.md。

## 已确认的协议

用户确认直接读取无 Skill 的冷启动经验，不额外执行一轮带 Skill 的 L1；
依据初始 descriptions 对 admission/final 独立路由并固定分组，比较同一 Skill 在同一批题上的执行效果。

L1 完成全部经验采集、聚类和初始建库后，L2 才开始。L2 提案串行，单个路由/验收阶段内部可并发。
每 Skill 的全部 source 卡按固定顺序分批（默认 16），每批一次提案，尾批不丢弃。

## 审计发现与修正

| 原实现问题或已不适用的设计 | 当前处理 |
|---|---|
| L1 执行和 L2 更新重叠，存在旧版本经验和过期库快照 | 删除异步任务队列、线程更新和过期快照重试 |
| 冷启动结果无法直接进入 L2，入口检查历史代码签名 | 独立加载完整冷启动；历史代码签名保留为来源，新 L2 单独冻结实现 |
| 所有 Skill 共用 admission 前 32 题，每次提案重新路由 | 路由全部 admission 题一次，各 Skill 只用自己的全部固定分组 |
| 在线 8/4/16 门槛用于已经静止的完整经验集会留下小组/尾批 | 固定离线批次，处理所有卡；没有证据新增等待或无界重试 |
| 只修改 description 仍可因重采样改变评分 | 执行 body 相同时复用评分，description-only 不能获胜 |
| 空验收分组可能被错误当成低分或借用其他组数据 | 明确 no_admission_tasks，不编辑、不接受；空 final 组率为 null |
| 恢复中任务表缓存可能掩盖磁盘任务变更 | 加载冷启动时刷新任务表并校验历史数据 hash |
| admission/final 被互换时，仅源任务映射检查不够 | split/config 必须与原 manifest 一致；同时校验发现阶段卡片 hash（存在时） |
| Skill 写入与验收日志写入之间中断 | 先写批次事务，再写两个版本/结果日志，恢复按批次顺序重放 |
| L3 策略写入与证据消费之间中断 | 策略与决定写事务，恢复不重复生成或消费 |
| 未生成补丁、格式无效、重复提案可能造成同证据循环 | 记录本批结果并继续下一固定批次；无提案不计入 L3 已评分证据 |
| 首次成功、无修复信号的批次被标为 negative | 新增 no_repair_signal，避免错误描述证据类型 |
| 通用异常分类引用未定义常量 | 修复为明确失败标签；provider/环境错误不进入普通失败评分 |
| 旧日志消费 API 只消费接受的经验 | fixed_batch 的所有已完成判定均计入消费，保留历史在线日志兼容 |

保留的必要约束：source/held-out 隔离、原始经验来源、固定配对题目、真实测量后严格提高才接受、
逐题/逐批落盘、独占运行锁、可恢复事务、代码/配置/数据身份一致。
移除未验收直接提交的内部旁路；正式 L2 的任何接受都必须携带通过的验收结果。

## 验证

- 完整离线回归：100 项测试通过，包括 19 项串行 L2 集成测试。
- ALFWorld 原生 smoke：指定评测 venv 中 1 项通过，验证真实 reset/动作反馈/无指导协议。
- SearchQA：真实本地执行环境配合脚本模型，验证单次执行、Skill 注入及无 selector/指导重试。
- 恢复：执行异常不缓存为失败；重用已生成提案；Skill/判定和 L3/消费写入中断可恢复。
- 不变量：新旧 body 在同一 Skill 的固定分组上比较；相同 body 复用相同评分；
  source 卡逐题唯一覆盖；final 路由失败留在整体分母。
- 静态检查：重构核心模块的未定义/未使用符号检查、编译检查和 diff 空白检查通过。

## 证据范围

没有启动真实 LLM 的完整 L2/final 实验，不能声称模型效果提高。
ALFWorld 原生 smoke 不等于完整 RepairAgent 的真实模型端到端测试；该评测 venv 仍需满足
本仓库的 agent 依赖才能运行正式命令。运行前遵守工作区的环境与服务健康检查要求。

固定路由协议验收 body 的执行效果，不验证更新后 description 的路由效果。
冷启动卡片只用于初始建库。当前 evolve 会将当前 Skill 注入 source L1 重新采样，
并让 L2 只消费该轮的新经验卡；每轮卡片和 Skill 版本单独落盘，避免把冷启动证据
误归因于后续 Skill。
admission 可被多次用于接受决策，最终泛化效果须用单独 final 检查。
