# 实验计划：Planner–Reviewer 协同进化（第一版）

本文件是当前实验的设计与验收标准。它取代
[EXPERIMENT_PLAN_REVIEWER_COEVOLVE.md](EXPERIMENT_PLAN_REVIEWER_COEVOLVE.md)（已 deprecated）。
本文不声称已有 benchmark 结果；所有数字都必须来自固定 test 集上的独立评测。

## 1. 科研问题与假设

问题：一个只在**预测**中工作的 Reviewer，能否通过与真实环境的最小接触，变得足以替代大部分
真实执行，并在与 Planner 的往返中把 Skill 的演化推向"提议者如实、验证者准确"的状态？

- **H1（配对预测）**：让 Reviewer 看到"改动本身"（旧规则 → 新规则）并报告**配对增量** Δ，
  比让它对两个完整 Skill 各报一个绝对成功率再相减更准。绝对成功率中的大部分方差来自题目难度，
  与"这次改动是否有用"无关。
- **H2（抽检即校准）**：用少量真实抽检结果对预测做无偏修正（prediction-powered inference），
  即使 Reviewer 有系统偏差，决策也不会被带偏；Reviewer 越准，同等置信度所需的抽检越少。
- **H3（可核实的声明）**：要求 Planner 附上"触发条件 + 动作变化"的声明，并由一个冻结的独立
  判定者在两臂轨迹出现分歧时核实，能把声明从空口理由变成可被证伪的承诺，从而抑制夸大。
- **H4（双向记忆）**：Reviewer 从自己的错判案例中学习（高估 / 低估两类），Planner 从**真实结果**
  中学习（哪类改动真的有效、自己的声明兑现了多少）。两者都以真实结果为锚，构成团队博弈而非对抗。
- **H5（收益来源）**：收益来自"Reviewer 变准 + 抽检修正"，而不是更多候选或更长提示。
  必须与"同样的抽检预算下直接实测验收"（empirical）比较，否则无法排除"钱本来就花在执行上"。

"博弈"在这里是操作性设计：验收规则事先固定、不可被任何一方改动；激励通过**验收**（哪些改动能存活）
和**记忆内容**（下一轮看到什么）起作用。本文不声称形式化均衡，也不把 prompt 更新称为训练。

## 2. 数据边界

沿用固定的 `train` / `val` / `test`（50/25/25，实测 SearchQA 400/200/1400，ALFWorld 39/18/134）。

| split | 谁可以用 | 用途 |
|---|---|---|
| `train` | Planner | 跑 L1、产生经验卡、提出改动 |
| `val` | Reviewer、判定者、抽检 | 预测、抽检、决策；**抽检题在 val 内部随机抽样** |
| `test` | 无人 | 仅最终报告，绝不回流 |

对 Planner 的额外限制（防止 val 泄漏）：

- Planner 记忆只保存**改动层**的结论：这个改动是否有效、声明兑现几次、Reviewer 对它的预测与真实
  Δ 的差距。**不保存任何 val 题目原文或 task id。**
- Planner 看不到 Reviewer 的逐题判断与理由（那会泄漏 val 内容，并诱导 Planner 迎合 Reviewer）。

本版**不**另划 calib split：抽检在 val 内进行，一份执行同时用于"本轮决策纠偏"和"下一轮记忆"。
由此带来的轻微 val 污染是已知代价，最终结论一律以 test 为准。

## 3. 一轮的流程

| # | 步骤 | 输入 | 输出 |
|---|---|---|---|
| ① | 提议（Planner） | 当前 Skill、本批 train 经验卡、Planner 记忆 | 一条 structured 改动 + **声明** |
| ② | 预测（Reviewer） | 每道 val 题、当前 Skill、改动与声明、Reviewer 记忆 | 逐题：会不会触发、预测 Δ |
| ③ | 抽检（真实环境） | 随机抽到的 val 题 | 旧 / 新 Skill 各跑一次，真实 Δ 与两条轨迹 |
| ④ | 判定（独立判定者） | 规则、声明、**首个差异片段**（仅当两臂轨迹有分歧） | 四类之一：与规则无关 / 符合声明 / 不符合声明 / 无法判断 |
| ⑤ | 决策（固定规则） | ②的预测、③的真实 Δ | 接受或拒绝 |
| ⑥ | 记账 | ①–⑤ 的全部记录 | 账本新增若干行 |
| ⑦ | 更新记忆 | 账本 | Reviewer 记忆（每轮）与 Planner 记忆（每轮，仅改动层聚合） |

决策规则（实验开始前写定，双方都不得改动）：

1. 点估计：`Δ_hat = mean_over_panel(Δ̂) + mean_over_sample(d − Δ̂)`（PPI 估计）。
2. 置信下界由抽检对的配对差 `d − Δ̂` 的方差给出，方法与小样本处理在实现中固定并记录。
3. **下界 > 0 才接受。**

该规则的两个性质是整个设计的支点：**抽检修正后的估计对 Reviewer 的偏差是无偏的**（因此 Planner
无法通过讨好 Reviewer 让无效改动通过）；**Reviewer 越准，同样的置信度需要的抽检越少**。

## 4. 组件定义

**声明（claim）**：两项必填——`trigger`（什么情况下这条规则会生效）与 `action_change`（触发后动作
从什么变成什么）。由 Planner 与 edit 一并产出，随 batch journal 冻结（不写入 `Skill` 持久格式）。

**Reviewer 输出**：每题一次调用，报告 `trigger_probability` 与 `delta_probability`（或 better/same/worse
三分类换算），附一句理由。同一改动下逐题判断可并行，但每题只调用一次。

**判定者输出**：四类之一 + 一句理由。冻结、不看成绩、看不到 Reviewer 的预测和 Planner 的信誉。

**账本**：每个改动 × 每道抽检题一行，字段为
`round · batch · family · 改动（节/操作/目标规则/新文本）· claim_id 与声明文本 · Reviewer 预测 ·
是否被抽中 · 判定类别 · 两侧结果 · 真实 Δ · 决策`。
账本是从 batch journal 与两个执行缓存**派生**的，可随时重算。

**Reviewer 记忆**：错判案例库，两类——高估（看似有用，实则无用）、低估（看似无用，实则有用）。
每个案例包含 val 题、改动与声明、当时的预测、判定类别、分歧前后的动作、真实结果。检索规则固定
（同节、同类改动，正误案例各占一半，排除当前改动与该题本身）。

**Planner 记忆**：提案历史，只到改动这一层——该改动的结论（有效 / 无效 / 证据不足）、声明兑现
（触发 n/N、符合声明 n/N）、Reviewer 对该改动的预测与真实 Δ 的对比。

## 5. 预注册指标

| 层级 | 指标 | 说明 |
|---|---|---|
| **主指标（Reviewer）** | 逐题 Δ-Brier skill score，相对"全部预测 Δ=0"的基线 | 只在配对样本上计算；按**候选聚类**做 bootstrap 置信区间 |
| **护栏（决策）** | 候选级错误接受率（被接受但真实 Δ ≤ 0）与错误拒绝率；regret | 只有错误接受下降、错误拒绝上升时，说明 Reviewer 只是变保守，不算变准 |
| **诊断** | 结果不一致的配对上的排序 AUC；判定类别分布 | 用于定位来源，不参与条件比较 |
| **判定者** | 与 ALFWorld 程序核对的一致率；SearchQA 人工标注一致率（N≈50）；重复判断稳定性 | 先于主实验完成，未达门槛则不启用机制项 |
| **Skill 质量** | test 上 paired 的 对→错 / 错→对 task IDs；最终成功率 | 最终结论一律用固定 test 集与逐题配对分母 |
| **成本** | 抽检次数、总执行次数、token、wall-clock | 用于画"成本—决策质量"曲线 |

主指标在看数据前固定；不得事后从多个口径中挑选。所有配对比较保留原始单元级记录。

## 6. 对照与消融

| 条件 | 候选 | 验收 | 声明核实 | Reviewer 记忆 | Planner 记忆 |
|---|---:|---|---|---|---|
| **A0** 历史参照 | 1 | `predicted`（旧协议，绝对概率） | — | — | — |
| **A1** PPI | 1 | `sampled` | off | off | off |
| **A2** +Reviewer 记忆 | 1 | `sampled` | on | on | off |
| **A3** 完整方案 | 1 | `sampled` | on | on | on |
| **A4** 无声明核实 | 1 | `sampled` | **off** | on | on |
| **A5** 同预算实测 | 1 | `empirical`（同样抽检量的全量实测） | — | — | — |

- 主比较 **A3 vs A2**（Planner 记忆的价值），**A2 vs A1**（Reviewer 记忆的价值），
  **A1 vs A0**（配对预测 + PPI 的价值），**A4 vs A3**（可核实声明的价值）。
- **A5 是成本逻辑的关键基线**：如果 A3 不能以更少的真实执行达到 A5 的决策质量，
  那么"用预测代替执行"的动机不成立，必须如实报告。
- 每个条件使用新的 run 目录；manifest 冻结 commit、模型与 role 映射、split、route、
  candidate count = 1、抽样参数、置信水平、记忆模式、判定者开关与 prompt 版本。

## 7. 审计不变量

以下每条都必须是可自动执行的检查；任一条不成立则该条件作废归档。

1. 抽检集 ⊆ 冻结 val panel，且由 manifest 中的种子确定性复现；记录抽样概率。
2. 账本中每个 (改动, 抽检题) 恰好一行；覆盖完整，不重不漏。
3. 点估计与置信区间可由账本逐行重算，与 journal 记录一致。
4. 判定者只在两臂轨迹存在分歧时被调用；其输入不含成绩、不含 Reviewer 预测。
5. Planner 记忆的文本不含任何 val 题目原文或 task id。
6. Reviewer 记忆只由当前轮之前的账本计算得出。
7. 声明在整批过程中不被改动：journal 与账本中的 `claim_id` 一致。
8. 两条轨迹完全一致时两侧结果必须相同（执行确定性的不变量检查）。
9. 每条 Reviewer 预测记录输入 hash（题目、改动、声明、记忆版本），可逐条重放。

第 8 条是**检查**而非保证：执行器已是 `temperature=0`，但远程服务的批处理仍可能引入差异。
若复现率不达标，分歧检测退化为粗粒度动作序列比较，并在报告中说明。

## 8. 实施步骤

任何完整 campaign 都必须在下列步骤全部通过后启动。每步单独提交、单独可审。

1. **声明**：Planner 输出声明，`parse_plan` 校验，写入 batch journal 并冻结；审计检查第 7 条。
2. **配对 Δ Reviewer**：新的 Reviewer 打分器（看到 diff 与声明，输出触发概率与 Δ）；
   决策规则暂用旧的"均值 > 0"以隔离变量。
3. **抽检 + PPI**：`acceptance_mode=sampled`，抽样、点估计与置信下界，审计第 1–3 条。
4. **轨迹分歧检测**：程序定位首个差异步骤并截取片段；审计第 8 条。
5. **独立判定者**：新 role、四类输出与解析、缓存；审计第 4 条；先用 ALFWorld 与程序核对做一次性校准。
6. **两份记忆**：Planner 聚合记忆与 Reviewer 案例记忆的构建、注入与版本化；审计第 5、6 条。
7. **接线**：CLI、campaign、manifest、文档。
8. **预检**：1–2 个 train task 的全链路 smoke、上述全部不变量、对照条件核对，通过后才允许完整运行。

## 9. 风险与失效条件

- **执行非确定性**：直接决定分歧检测与"触发"判断能否成立。先用小样本实测复现率，再决定是否启用第 4 步。
- **判定者自身误差**：只影响记忆与信誉，不影响是否接受；但必须报告其一致率，并说明它最多影响哪些结论。
- **样本量**：ALFWorld 每个 family 的 val 只有 3–5 题，抽样会退化为全量执行；SearchQA 小 family 为 11–15 题。
  小 panel 上 PPI 相对实测的节省有限，需在报告中按 family 规模分层说明。
- **交互轮数**：信誉与记忆需要多轮才能显现。若总轮数过少，Planner 一侧学不到东西，此时应报告"无效应"而非
  挑选数据。
- **共同盲区**：Planner 与 Reviewer 默认同模型，错误可能高度相关。判定者与真实抽检是唯一的独立信号，不可省。
- **val 轻微污染**：抽检在 val 内进行，Planner 记忆虽只到改动层，仍可能间接吸收 val 分布信息。
  最终结论以 test 为准；报告中必须写明这一限制。

## 10. 与旧协议的关系

旧协议的终止点：`docs/EXPERIMENT_PLAN_REVIEWER_COEVOLVE.md` 描述的 C0/C2/C3 条件（train 反馈、
模板规则、双侧绝对概率）已 deprecated。代码中对应的 `acceptance_mode=predicted` 与
`reviewer_update_mode=rules` 路径保留为 A0 历史参照与审计对象，不参与新协议的主比较。
新协议使用独立的模块与协议版本号；新旧 run 互不兼容，也不复用。
