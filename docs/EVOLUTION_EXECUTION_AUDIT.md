# 执行链与恢复审计（2026-09-23）

本次审查对象是 SkillExpand 当前闭环及 SearchQA、ALFWorld 的执行边界。
发现了实际实现缺陷并已修复。此前“闭环已完整验证”的表述不成立：旧测试曾手工构造
带轮次的经验卡，绕过了真实 L1 未写入 `evolution_round` 的问题。本次闭环测试调用真实
L1 runner，模型使用固定响应；原生环境验证另行执行。历史实验不能因此被追认为有效。

## 实际执行顺序

1. **冷启动**：只对 source 做无 Skill 的 L1；每题保留尝试、环境结果和最终总结。
   检查点与卡片通过审计后，发现 family 并生成初始 Bank v0。导入完整冷启动时校验
   数据、划分、卡片和初始库身份，保留历史来源，不重跑冷启动。
2. **开始 evolve N**：先写入 `evolution/round-N/input.json`，冻结所有输入 Skill 的
   完整内容及 source 任务集合。第一轮必须来自 v0；后续轮必须来自上一轮输出。
3. **本轮 L1**：沿用冷启动的 task-to-family 映射，所有 source 使用本轮冻结 Skill。
   沿用冷启动自主尝试及监督设置。每题独立落盘；全部完成且通过 L1 审计后才能进入 L2。
4. **本轮 L2**：只使用本轮新卡；每 Skill 每批最多 50 张，默认最多 3 个候选。
   批次身份来自轮次、Skill ID、任务和卡片 hash，不随 Skill head 改变。同一 Skill
   多个批次顺序更新，因此较后批次的 CURRENT 可能新于卡片实际执行的版本。
5. **候选与评审**：编辑器和 reviewer 都获得执行版本及尝试阶段。候选先按不同修改
   假设生成；相同 body 去重，证据不足时允许少于 K 个。reviewer 预测当前批次上的
   修复与回退，确定有效赢家或保留原版；不运行 admission，不修改 description，L3 冻结。
6. **提交及审计**：先保存决策，再追加 Skill 版本。用只读方式重放已缓存的生成及
   评审产物，检查全部决策路径，包括无候选、无效评审和 hold。恢复提交也先做该检查。
   轮末核对完整版本链并写入审计，随后才允许下一轮。
7. **final**：显式启动，要求已有 evolve 完整且审计通过。使用初始 description 固定
   路由、当前 Skill body 单次执行；无反思、无监督、无经验卡注入。逐题落盘后独立
   复算整体及每 Skill 指标。路由格式失败计入总体分母；服务错误停止出分，留待恢复。

`--phase l2`、`evolve` 的演化语义现在一致，均包含本轮带 Skill 的 L1。
`all` 是冷启动加演化，不自动运行 final。`--evolve-rounds N` 表示累计目标轮数，
允许 N 增至 N+1；旧轮卡片保留作审计，不送入新一轮 L2。

## 发现与修复

| 问题 | 影响 | 修复位置与行为 |
|---|---|---|
| L1 未记录真实轮次 | 第二轮经验无法可靠区分，闭环测试绕过真实路径 | `l1/runner.py` 写入轮次及执行身份；真实 runner 集成测试 |
| 轮输入冻结过晚、批次 ID 依赖可变 head | 中断恢复可能混用版本或重复更新 | `l2/loop.py` 提前冻结输入，使用稳定批次身份，禁止旧协议混跑 |
| 编辑提示仍把所有卡当冷启动经验 | 新 Skill 的实际执行可能被当作无 Skill 证据 | `l2/editor.py`、`card_review.py` 显式传递并解释执行版本和 CURRENT |
| 中断消耗尝试额度，监督尝试不能恢复 | 网络故障被误作模型能力不足 | 只计算完成的尝试；中断保留审计，恢复重新开始未完成 episode |
| 总结请求失败被永久写成空经验 | 暂时服务故障造成长期丢失学习结果 | 执行完成后保留待总结状态；恢复只补总结；无效响应仍不重采样 |
| Search 无限重试、查询状态跨 episode 残留 | 卡死，或新尝试读取旧上下文 | Search 工具异常上抛；reset 清理可变查询状态 |
| ALFWorld 终止信息丢失 | repeated-action 截断标记被覆盖，原生 done 未被采用 | 保留 truncated、采用原生 done、reset 清除终止原因；成功仍取引擎 won |
| 模型多层重试、原生环境或 worker 卡住 | 长时间无进展、难以续跑 | 单层有界请求重试；环境调用期限及独立进程进度看门狗 |
| 按提交顺序收集 worker 结果 | 慢任务阻挡已完成任务落盘 | 先完成先落盘；通过任务 ID 对齐 |
| 审计未连通原始执行到最终指标 | 错误卡片、版本或分母可能未被发现 | L1 环境结果核对、轮次决策重放、final 逐题独立复算 |
| 请求汇总跨进程丢失或存在未配对 start | 成本低估或无法完成审计 | 从请求日志重建已知用量，记录 abandoned，拒绝重复及未匹配 ID |

ALFWorld 动作语义、空容器信息、示例及反馈规则仍限定在 ALFWorld adapter、prompt
和环境封装中。SearchQA 使用独立 adapter 与本地上下文索引，判分仍是规范化精确匹配。
通用层只负责执行记录、预算、恢复、证据校验和演化调度，不注入 ALFWorld 操作规则。

## 恢复与超时

| 边界 | 默认行为 |
|---|---|
| 模型请求 | 每次 300 秒，额外重试最多 2 次；客户端不再叠加重试 |
| ALFWorld reset / step / close | 主线程信号超时 120 秒 |
| 原生进程池 | 即使单 worker 也隔离进程；连续 3600 秒无单元完成则退出进程池 |
| L1 episode 中断 | 保留逐动作记录，恢复从环境初态重跑该 episode；不占用完成尝试预算 |
| L1 总结中断 | 完成轨迹不重跑，仅重新请求尚未获得的总结 |
| L2 服务中断 | 复用已有假设、候选及逐卡评审，只补缺失请求 |
| 决策已落盘、版本未提交 | 验证缓存决策后恢复一次提交；已有版本须与决策完全一致 |
| final 部分完成 | 复用已完成路由及逐题成绩；服务错误不作为 benchmark 失败缓存 |

进程池期限是“没有任何单元完成”的进度期限，不是每题总时限。它弥补 Python 信号
无法打断某些原生调用的限制。退出时其他正在执行的单元也会中断，已有检查点可续跑。
直接调用底层环境 API 不具备进程池看门狗，应使用正式调度入口执行实验。
磁盘写入采用任务锁、运行锁及原子检查点；命令行另有 campaign 排他锁。
长任务仍须按工作区要求以独立进程会话启动并核对准确 PID。

## 验证证据

- 离线自动测试：142 项通过。包含真实 SearchQA 本地执行、冷启动、两轮真实 L1
  runner 驱动的演化、候选/评审、独立 final 路由及分母核对。
- 故障注入：部分 L1 后中断、批次之间中断、决策落盘后提交中断、执行超时、监督
  尝试中断、总结超时、评审服务失败、原生 worker 无进展、请求日志恢复。
- 破坏性校验：修改卡片、检查点、原始评审或 final 汇总后，审计拒绝通过。
- 隔离与不变量：source 覆盖、固定路由、冻结 description/L3、输入 Skill 身份、
  旧轮卡片不复用、已完成单元不重新采样、ALFWorld 专属规则不进入 SearchQA prompt。
- ALFWorld 指定 benchmark venv：2 项原生测试通过，覆盖真实 reset/观测、Skill 注入、
  L1 及恢复、无可用监督、重复动作终止，以及单次 final 执行和原始环境结果。
- Ruff 静态检查、编译检查和 diff 空白检查通过。

本次没有启动完整付费实验，也没有据此报告成功率增益。原生测试使用固定模型响应，
验证的是交互及恢复语义，不是 LLM 的解决能力。正式长实验前仍需真实服务生成健康
检查、当前模型的 1–2 题全链路预检和预先固定的指标。

## 审计能证明什么

审计验证保存的执行、卡片、缓存决策、Skill 历史和指标是否一致；它不能证明自然语言
lesson 的因果正确性，也不能保证候选语义足够不同或 reviewer 预测准确。只有独立 final
实测能说明性能。未知请求 token 不凭空补齐，成本结论必须注明不完整。

旧冷启动可以作为历史输入导入；本次增强的逐事件审计只适用于新执行记录，不能直接
套用于缺少这些字段的历史记录。新的 evolve/final 必须使用新目录，不能混入旧代码指纹
下的中途产物。外部 TextWorld 仍有 PDDL 文件关闭警告，本次测试未出现执行失败。
