# Fixed three-task bundled historical-input ablation

Tasks are cancel-async-tasks, multi-source-data-merger, log-summary-date-ranges.
The last two were seen in prior diagnosis but were not used to tune this frozen
module. They are not blind tasks. Same-task fresh environments are not new-task
generalization.

All three use the E6 final library skill selected by original attempt 1. Source
body/resources are archived, then uniformly removed because their historical
success ancestry cannot be untangled. The common sanitized-original control and
both generation arms retain the audited generic routing metadata and only the
inert body "Follow the public task requirements.". No targeted replacement is
written. This changed input is explicitly distinct from the previous experiment.

A includes all nine preselected E1/E4/E6 historical records, loaded skill text
and existing original memory cards. B excludes success and unknown reward rows,
all historical loaded-skill text, all memory cards, and all free-form historical
tool contents/commands/narration. B retains failure structural metadata only.
This conservative joint removal also discards useful diagnosis. It does not
separately identify the contribution of successful traces, source echoes or
leakage. Public contract, common sanitized seed, native module/system message,
generation settings, execution settings and budgets are identical between arms.

A and new development feedback use the same ordered tool-result extractor with
8192-character explicit head/tail truncation, excluding entire steps containing
restricted evaluation paths/markers before truncation. B history masks ALL text,
so code in any language or echo form is removed without task-specific matching.
Raw originals are archived. Historical filtering is fixed data processing for
this experiment, not memory-strategy optimization. Both arms' new feedback may
contain their own autonomous implementations but never old research answers or
hidden verifier output. Feedback includes official reward and allowed tool
observations, never evaluator stdout, assertion contents or researcher diagnosis.

Each task has exactly five shared sanitized-original control slots. Each arm has
at most two generation slots, each invoked once with no automatic retry. Every
usable candidate gets exactly three new development slots. Candidate 2 uses only
its arm's candidate 1 package and exact three new feedback records; if candidate 1
has no usable package, it uses the common seed and no new feedback. Generation
no_change, malformed output and transport failures are retained, not retried.

After both slots finish, choose the generated candidate with the greatest number
of valid official reward=1 development results. Unresolved results give no
positive evidence and remain distinct from zero. Ties select the earliest slot;
a valid package with zero successes remains selectable. No usable generated
candidate means no final execution for that arm. Freeze selection and full skill,
then run exactly five final slots. Final results never enter generation or
selection. No failure/initialization timeout is replaced. Maximum trial count is
3 * [5 + 2 * (2 * 3 + 5)] = 81. This counts executor trials, not multi-step API
requests; frozen HTTP transport retries remain unchanged and are reported.

Native SkillEditor.propose_package source and system message are frozen at
published commit 255a67c, without changes for these tasks. Qwen request model is
openai/qwen3.6-flash-distill; raw response model identity is recorded separately.
Agent budget is 7200 seconds; request top_p=.95/max_tokens=65536/top_k=20 with
thinking/preserve/interleaved enabled. Frozen original task definitions, runtime,
provider path, cache and official verifier are preserved. Harbor trial retries
are zero. Snapshot retries remain three. Sandboxes are deleted after execution;
host traces/logs/mounted packages remain, not the live final /app filesystem.

All slots persist reservation/start before execution and cannot rerun after a
partial crash. Across all tasks/arms/phases, authoritative sandbox IDs must be
new and unique relative to historical IDs. Missing IDs/config/artifact failures
are unresolved. A duplicate or historical identity invalidates all affected
records and blocks further calls for the entire run; no replacement is made. Valid AgentTimeoutError rewards remain valid official outcomes.

Completion means finishing the fixed protocol and reporting every real result,
not achieving any particular score. A-only gains show combined-information
sensitivity, not causal proof of leakage. B success supports nondependence on the
removed material under this protocol. Generation sources, exact requests, usage,
rounds, durations and observed resource reads/invocations are delivered. Commands
alone do not prove a helper ran correctly. No extra robustness/ablation Qwen
trials are permitted within this stage.

Coordination retains the live shared worker limit of 250, verified from the
existing active E10 driver. Nine independent drivers reserve a conservative
maximum of 45 executor workers in the existing capacity ledger. At preflight,
100 workers were already reserved, so this run fits with 145 total. This controls
scheduling only; measured Qwen request parameters and trial budgets are unchanged.
